# 运动学动作设计

这份参考用于新做或修正人形角色的 Idle、Walk、Run、Jump、Flight、落地动作，尤其适合处理动作生硬、反膝、滑步、脚底漂浮、循环接缝和动画速度与控制器脱节。目标是让动作先符合受力与重心变化，再用幅度和节奏表达人物性格。

## 先诊断哪里不连续

把问题分成四类，避免只靠增加关键帧碰运气。

- **姿态问题。** 髋、膝、踝、躯干或手臂方向错误，轮廓不支持动作意图。
- **时序问题。** 缺少承重、制动、推进、滞空或缓冲阶段，关键姿势之间平均分配时间。
- **约束问题。** 支撑脚滑动，最低脚底离地，动画和控制器同时驱动根节点或上下起伏。
- **混合问题。** 状态切换重启动作、淡入时间不合适，动画时长与物理阶段或移动速度不匹配。

先从正面和侧面查看关键阶段，再进入游戏判断速度。单张正面图很容易掩盖反膝、前后摆反向和落脚漂移。

## 先标定骨架，随后设计姿势

自动绑定骨架的局部轴不能凭名称猜。对大腿、小腿、脚、上臂、前臂和脊柱分别做小幅正负旋转测试，每次只动一个关节，输出侧视图并记录方向。至少确认以下映射。

- 大腿向前抬与向后伸对应哪个符号。
- 膝关节正向是否为自然屈曲，负向是否会反膝。
- 踝关节背屈与跖屈的方向。
- 上臂向前摆、向后摆和侧展方向。
- 脊柱前倾、后仰和侧倾方向。

需要按世界轴构造旋转时，用 rest pose 把世界轴转进骨骼局部空间。不要把同一组 Euler 数值复制到不同来源的骨架。

```python
rest = pose_bone.bone.matrix_local.to_quaternion()
local_axis = rest.inverted() @ Vector(world_axis)
pose_bone.rotation_quaternion = Quaternion(local_axis, angle) @ current
```

关键帧四元数写入前对上一帧调用 `make_compatible`，避免同一方向使用相反符号表示时产生长路径旋转。

## Walk 按完整步态组织

一个步态周期从同一只脚的初次接触开始，到它下一次接触结束。普通行走中，支撑阶段约占六成，随后进入摆动阶段。制作时至少检查这些事件。

1. **初次接触。** 前脚脚跟或符合角色鞋型的接触点落地，膝盖接近伸展但不锁死。
2. **承重反应。** 前脚逐渐踩实，膝盖轻屈吸收冲击，骨盆转移到支撑侧。
3. **中期支撑。** 重心越过支撑脚，上身保持可控，另一条腿向前摆。
4. **末期支撑与蹬离。** 支撑侧脚跟抬起，重心移向前掌，随后脚趾离地。
5. **摆动。** 膝盖屈曲以保证离地，腿向前送，接触前逐渐伸展。

对侧手臂与腿自然反向摆动。人物性格通过幅度和姿态表达。谨慎旅人可以缩小摆臂、略收肩、步幅克制；自信战士可以扩大胸廓旋转和蹬地；疲惫人物可延长双脚支撑和承重时间。不要删除支撑、承重和蹬离来表达克制，那会让角色像在平移。

已有质量较好的源步态时，优先保留其下肢相位和足部接触，只压低肩臂、脊柱或头部的幅度。对四元数从单位旋转到源姿态做球面插值，比逐轴缩放 Euler 更稳。

## Jump 按受力方向组织

反向跳至少需要下沉、制动、推进、腾空和落地吸收。每个阶段都要改变重心或关节速度。

- **下沉。** 髋膝屈曲，重心下降，手臂后摆或收拢。
- **制动。** 重心仍在下降，但下降速度减小；最低点不能直接跳过。
- **推进。** 髋、膝、踝由近端到远端伸展，手臂配合上摆。
- **腾空。** 根节点由物理系统控制抛物线，骨骼保持平衡和准备落地，不再假装持续蹬地。
- **落地吸收。** 脚先接触，髋膝随后屈曲，躯干允许少量前倾，最后恢复站姿。

如果游戏使用重力，动画时间应和物理滞空时间接近。忽略空气阻力时，回到同一高度的滞空时间可用 `2 * jump_speed / gravity` 估算。动画不负责改变角色世界高度，控制器不再额外缩放腿部模拟同一次跳跃。

动画包含预蹲时，控制器不要在按键当帧施加向上冲量。用起跳事件或与推进帧对齐的短延迟触发冲量，保证预蹲发生在地面上。把预蹲和落地吸收的关键帧逐帧接地，腾空阶段保留自由高度。

## Idle 和 Flight 也要有重心逻辑

Idle 先选一个明确支撑关系。呼吸主要影响胸廓和肩带，幅度小于换重心；头部观察动作不要和呼吸严格同频。首尾姿态相同，中间变化可以不对称，减少机械循环感。

Flight 先确定玩法语义。稳定滑翔可以用展开但不水平僵直的双臂、稍屈的膝和小幅平衡修正；持续拍翼只适合角色确实有相应结构。俯仰、滚转和航向通常由控制器外层节点驱动，骨骼动作负责轮廓和局部修正，避免两层重复倾斜。

## 接地与 root motion

先决定谁拥有水平位移。

- 控制器驱动时，清除动作中的平面 root motion，动画只表现步态。
- 动画驱动时，由 root motion 推进角色，碰撞和网络同步也要接受这一来源。

控制器驱动的 Walk 清除水平位移后，逐帧求变形网格的最低足底高度，再校正角色根节点。每帧先设帧并更新依赖图，再读取 evaluated mesh；不要使用静态包围盒。Jump 只接地预蹲和落地关键帧，Flight 以及 Jump 的腾空阶段保留离地。

支撑脚仍然滑动时，检查动画一个周期内控制器前进的距离。它应接近角色在该周期里的视觉步幅。

```text
每周期位移 = 控制器速度 × 动画周期时长 ÷ 播放倍率
```

先配播放倍率，再在不破坏玩法节奏的范围内调整控制器速度。角色两秒穿过几个身高，同时播放慢步动画，任何插值都救不了滑步。

## 曲线与状态混合

稀疏关键姿势优先使用 Bezier 和 Auto Clamped，让速度在姿势附近自然变化，同时限制过冲。高密度重定向或逐帧采样动作应保留足够采样，不要用少量自动曲线抹掉足部接触。

循环动作检查第一帧与末帧的姿态、速度方向和根节点位置。状态切换使用短淡入淡出；一次性 Jump 在离地时播放一次，落地后回到 Walk 或 Idle，不在每帧 reset。Jump 播放时长应覆盖实际物理跳跃，Flight 和 Idle 才持续循环。

## 最小验收

根据项目选择 3 至 5 组，至少包含下面前三类。

1. 正面和侧面检查 Walk 的接触、承重、中期支撑、蹬离，确认没有反膝和脚底漂浮。
2. 低速和正常速度各走两到三个周期，检查支撑脚滑动、循环接缝、走停淡入淡出。
3. 检查 Jump 的上升、最高点、下降、首次接触、最大屈曲和恢复，并核对动画时长与物理时间。
4. 检查 Flight 的巡航、转向、升降和着陆，确认控制器与骨骼没有重复倾斜。
5. 在目标设备和失败回退路径验证输入、状态机与动画名；Web 项目同时检查文本状态、截图和控制台错误。

保留一组修改前后视频和阶段图。视频判断节奏、滑步和循环，侧视阶段图判断关节方向、支撑关系和轮廓。测试通过以后仍要看这些素材，数值正确不能代替动作自然。

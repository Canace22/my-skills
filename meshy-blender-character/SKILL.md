# 多服务游戏角色与生物制作接入

把人形角色或动物伙伴做成符合目标游戏身份、体量和玩法的资产。沿用已确认的制作管线和美术选择；用户已指定 GPT → Meshy → Blender MCP、混元 3D → Blender 或其他明确流程时，不用几何体拼装、贴图平面或其他生成器冒充该流程。

## 先确定角色属于哪个世界

定向读当前场景、剧情与角色身份、参考图、现有加载器和控制器。检查工作区改动。先区分人形或非人形、玩家或 NPC、静态展示或需要动作，再确定实际接入入口；不要把角色预览、法术演示和游戏本体混为一处。

用简短设计说明把身份对应到轮廓、材质、配色、随身物件和动作气质。人形角色关注衣料、体型和道具；动物关注品种体态、年龄、耳朵、口鼻、四肢、尾巴和毛色分区。角色与场景不匹配时先修正设计方向，单纯提升模型精度解决不了身份问题。沿用已有明确选择，不重复索要确认；只有影响设计的关键信息缺失时才问。

## 选择生成服务

用户指定服务时优先使用该服务。未指定时按当前可用能力、输入类型、预算和后续绑定需要选择一次，不为“比较效果”默认在多个平台重复消耗额度。

- **Meshy**：已有 Meshy 任务、需要续跑既有任务，或项目已经依赖其多图、绑定和任务记录时，读 [Meshy 任务与资源管理](references/meshy.md)。
- **腾讯混元 3D**：用户指定混元、希望先用其网页免费额度试做，或需要其当前官方提供的文生/图生、多视图、拓扑、绑骨或动作能力时，读 [腾讯混元 3D：网页与 API 路由](references/hunyuan3d.md)。网页创作引擎和腾讯云 API 是两种入口；只使用当前入口真实显示或文档明确支持的能力。
- **其他服务**：先确认可下载格式、授权、费用、任务恢复方式和后续 Blender 可编辑性，再复用本 Skill 的出图、整理、接入与验收部分。没有证据时不声称支持绑定、动作或商业使用。

## 制作流程

1. **出图。** 使用可用的 imagegen 技能和正式图像生成工具。主参考采用完整主体、清晰分离的肢体、中立姿势、均匀光照与简单背景。人形强调手腕、五指和完整脚部；四足动物强调两眼与口鼻可读、四脚落在同一地面、远近侧腿可分、尾巴不遮挡身体。真实照片若有运动、草地遮挡或浅景深，先整理成简化毛发表面的建模图。需要多视图时保持同一设计，用独立文件提供正侧背，不把拼图误当单视图输入。保存原图、项目副本和提示词。
2. **生成。** 只读本次选定服务的参考页。复用已有配置和任务，按版本记录服务、入口、全部输入摘要与任务 ID。模型完成后检查正面、侧面、背面、面部、肢体分离和尾巴；明显失败时停止后续付费步骤。优先保存服务原始产物，再复制一份进入 Blender 流程；远程临时链接不能作为项目资产来源。
3. **可选绑定与动作。** 只对当前入口明确支持、且玩法确实需要动画的资产提交绑定或动作任务。网站上没有对应功能时，不把同品牌云 API 的能力算作已经完成。非人形或静态 NPC 不默认调用人形绑定；自动绑定结果仍要检查骨骼层级、权重、关节弯曲和动画重定向。
4. **Blender 整理与动画。** 读 [Blender MCP 与游戏接入](references/blender-game.md)。静态资产也要完成尺度、朝向、接地、材质和运行时导出。需要新做或重做 Idle、Walk、Run、Jump、Flight、落地，或用户反馈动作生硬、滑步、漂浮时，另读 [运动学动作设计](references/kinematic-animation.md)；该参考以人形为主，四足动作必须从真实骨架和步态重新标定。优先使用已连接的 MCP；否则可用附带的真实 stdio MCP 客户端连接本地插件。先确认场景，再修改。保留可编辑网格、可用骨骼、动作和打包贴图的 `.blend`，另导出游戏版。
5. **游戏接入。** 确认尺度、前进轴、脚底位置与变换层级。若请求只是替换 NPC 外观，优先保留现有移动、碰撞、交互、镜头和存档，只替换视觉层；多个静态实例可共享几何与材质但保留各自变换。骨骼动作与旧程序化关节代码不能同时控制同一组关节。加载异常时恢复原有可玩回退。
6. **验证交付。** 用 `scripts/inspect_glb.py` 检查导出的 skins、动画名、材质与三角面估算，再在 Blender 和游戏里实际看图、操作。Web 游戏使用可用的 develop-web-game 技能。功能检查不能替代侧面体积、脚底接地和材质的视觉检查。

## 验收与交付边界

根据本次改动选 3–5 组实际测试，通常包括：加载与尺度、正侧背体积与接地、走停/跟随或展示、交互/存档、目标设备与加载失败回退。修正后只重跑受影响的检查；不要为截图通过而改动无关剧情或系统。

交付游戏入口、角色预览、`.blend` 与运行时模型，以及可复现脚本和任务记录。记录实际生成服务和网页/API 入口；说明模型是否静态、完成了哪些动作、真实验证范围及尚未做的布料、手指、尾巴或表情功能。明确区分原始生成、自动绑定、现成动作整理和自行制作的动作。

仅在授权范围内提交生成任务，不购买额度或自动无限重试。一次生成若有明确结构缺陷，可在余额允许且改进输入后做一次有针对性的版本化重试；仍失败就停下报告，不继续烧额度。不可用的工具要如实说明；只出图、只生成模型或仅能在 Blender 预览，都不能报告“已接入游戏”。

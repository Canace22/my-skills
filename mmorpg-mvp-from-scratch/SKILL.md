# 从零做多人 RPG MVP

一次做完要跑通四件事：**能动、能打、能接任务、别人能看见你**。
少一件都不叫 MVP，多一件就开始超期。

---

## Step 0 · 先问，别急着写

三个问题不问清楚，写出来的多半是废的。用 AskUserQuestion 一次问完：

1. **形态** — 网页 2D 俯视角联机 / 网页 3D 联机 / 单机原型 / 只要设计文档
   默认推荐 2D 俯视角联机：几小时能跑起来，且真的能验证 MMO 的核心循环。3D 的美术成本会吃掉全部时间。
2. **必须跑通哪些系统**（多选）— 移动同步 / 战斗 / 任务剧情 / 背包装备升级
3. **题材与 IP 边界** — 如果用户报的是商业 IP（塞尔达、原神、魔兽），主动提供「XX 式原创世界观」选项：
   沿用经典结构（勇者—公主—魔王—神器），换掉全部专有名词。用户几乎都会选这个，以后想公开发也没风险。

不问清楚就动手是这个任务最大的浪费来源。

---

## Step 1 · 数据先行，一个文件装完

**先写 `data.js`，再写任何逻辑。** 所有数值和文案集中一处：

```
世界观常量（大陆名、主角、反派、开场白）
章节表        ← 全服共享的剧情进度
物品表        ← 武器/防具/消耗品/任务道具，带 atk/def/heal
怪物表        ← hp/atk/def/exp/speed/仇恨半径/攻击距离/冷却/掉落表
NPC 表        ← 像素坐标 + 名字
任务链        ← giver/turnIn/objective/reward/requires/chapter
刷新点        ← 怪物类型、中心点、半径、上限
升级曲线      ← 一个函数
玩家基础属性
```

好处很实在：调平衡只改一个文件；世界观和代码解耦，换题材不用动逻辑；
后面写测试时所有断言都能引用这里的真值，不用硬编码魔数。

任务的 `objective.type` 只需要三种就够覆盖一条完整主线：
`kill`（打怪计数）、`collect`（背包里有几个）、`interact`（和场景物件交互几次）。

---

## Step 2 · 服务端权威，职责切干净

**客户端只发输入意图，位置/伤害/掉落全由服务端裁决。** 这是唯一正确的起手式，
后期想改成权威几乎等于重写。

```
server/data.js     数值与文案（Step 1）
server/world.js    固定种子地图生成 + 碰撞检测
server/game.js     世界状态、主循环、玩家增删、交互、快照
server/combat.js   伤害公式、攻击判定、怪物 AI、死亡掉落
server/quests.js   接取/进度/交付，纯函数，状态挂在 player 上
server/index.js    HTTP 静态服务 + WebSocket 消息路由
public/game.js     Canvas 渲染 + 输入采集 + 本地预测
```

`combat.js` 和 `quests.js` 接收一个注入的 `ctx`（players / mobs / fx / log / grantExp），
不直接 import game.js，避免循环依赖，也让测试能塞假 ctx 进去。

**关键参数**（验证过手感的默认值）：

| 项 | 值 |
|---|---|
| tick 频率 | 20Hz（50ms） |
| 玩家速度 | 130 px/s |
| 攻击范围 / 冷却 | 46px / 500ms |
| 视野裁剪半径 | 700px |
| 怪物重生 | 12s，精英 45s |

## Step 3 · 按依赖顺序实现

顺序不能乱，每一步都建立在前一步之上：

1. **地图与碰撞** — 固定种子生成（服务端算完随快照下发，客户端不重算），
   碰撞用分轴移动：撞墙时保留另一根轴的位移，贴墙走才不会卡死。
2. **移动 + 多人同步** — 服务端 tick 里积分移动，广播视野内实体。
   客户端跑一套**和服务端完全相同**的碰撞逻辑做本地预测，收到快照后按 15% 平滑对账，
   偏差超过 60px 才硬拽回去。没有预测的话，移动会有肉眼可见的粘滞。
3. **战斗** — 攻击判定用「朝向偏移出去的一个圆」，命中圆内全部目标。
   怪物 AI 三态：巡逻（离家太远就往回走）、追击、攻击。
   仇恨中的目标追击半径放大 1.8 倍，否则怪会在边界反复丢失目标抽搐。
4. **任务与剧情** — NPC 交互返回一个「选项列表」，每项带 accept/turnin/none 三种 action。
   接取 kill 类任务时**清零该怪的历史击杀数**，否则老玩家一接任务就直接完成。
5. **UI** — HUD、任务面板、背包、对话框、聊天、伤害飘字。

**让它有 MMO 味的一招**：全服共享章节。关键任务交付时推进一个全局章节号，
广播世界公告，第三章召唤一只血厚的世界 Boss，经验和掉落按参与伤害的人头发。
成本很低，但这是单机原型和 MMO 的分水岭。

## Step 4 · 三层验证，一层都别省

**第一层：逻辑测试**（`node test/logic.test.js`，assert 裸写，不引框架）

至少覆盖这几类，每类 2-4 条：

- 碰撞：出生点可站、边界是墙、水面不可站、**任意大位移的落点必须仍然可站**
- 战斗：范围内命中掉血 / 范围外打不到 / 冷却内第二次无效 / 击杀给经验和掉落 / 死后到点重生
- 成长：经验够了升级且属性提升 / 装备武器加攻击、再点一次卸下 / 消耗品回血并扣数量
- 任务：前置未完成不能接 / 没打够不能交 / 交付后扣材料给奖励 / 接取时重置历史击杀
- 世界：关键任务交付推进全服章节并产生公告 / 快照只含视野内实体

**第二层：联机冒烟**（`node test/net.test.js`）
spawn 真实服务器 + 两个 ws 客户端，验证：都收到 init、互相在快照里可见、
按方向键后坐标真的变了、能接任务、聊天广播到对方、断线后从世界移除。

**第三层：无头浏览器**（Playwright）
进游戏 → 按 E 对话 → 点接任务 → 走到怪群 → 连按攻击 → 截图。
**必须真的读那张截图**，只看「无 console 报错」会漏掉一整类问题：
画面噪点、UI 遮挡、血条误导、交互半径太小按了没反应。

## 反复踩到的坑

- **怪物实例上没有 `def` 字段。** 数值在 `MOBS[m.type]` 里，实例只有 hp/x/y。
  写成 `damage(p.atk, m.def)` 会得到 NaN，怪物血量变 NaN 后永远打不死，而且不报错。
- **测试别依赖随机生成地图的具体坐标。** 「(40,300) 往左撞墙」这种断言会因为种子里
  某个 tile 恰好是石头而挂掉。改成断言不变量：「任意大位移的落点必然可站立」。
- **交互半径给 90px 起步。** 70px 时玩家站在 NPC 旁边按 E 没反应，会以为功能坏了。
- **满血不画血条。** 每只怪头上顶一根红条，画面会像出了 bug。
- **地面装饰的对比度压低。** 草丛、石头的装饰色和底色差太多，满屏噪点，
  怪和玩家反而看不见。

## MVP 红线：这些不做

持久化存档、技能树与冷却条、组队与副本实例、Boss 阶段机制、
tileset 美术与 sprite 动画、输入序列号回滚、防作弊校验、匹配与分线。

全部写进 README 的「往下可以做什么」，**并在交付时口头点出第一优先项**——
通常是持久化，因为「重启服务器存档就没了」是用户下一分钟就会撞上的问题。

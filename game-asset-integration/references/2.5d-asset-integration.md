# 2.5D asset integration — inspection recipes and checklists

Depth for the parent skill: GLB fact extraction, size normalisation, and the acceptance pass.

## Inspect GLB facts without opening Blender

Read the JSON chunk directly — stdlib only, no Blender, no add-ons:

```python
import json, struct, glob, os

def glb_json(path):
    with open(path, 'rb') as f:
        _, _, _length = struct.unpack('<III', f.read(12))
        clen, _ = struct.unpack('<II', f.read(8))
        return json.loads(f.read(clen).decode('utf-8'))

for f in sorted(glob.glob('assets/models/**/*.glb', recursive=True)):
    j = glb_json(f)
    print(os.path.relpath(f),
          'skins=', len(j.get('skins', [])),
          'anims=', len(j.get('animations', [])),
          'nodes=', len(j.get('nodes', [])))
```

Reading the numbers:

| Reading | Meaning |
|---|---|
| 0 skins, 0 animations, 1 node | static single mesh — no rig to reuse; idle/walk must be authored |
| several nodes, 0 animations | may still be flat geometry; check for a real joint hierarchy before assuming a rig |
| `skins >= 1` | rigged — read `skins[0].joints` for the bone list and name attachment points after it |

Print animation clip names too (`a.get('name')`): they are what the runtime looks up by, so a
mismatch between clip names and the code that plays them is a silent no-op.

## Real bounding box

Accessor `min`/`max` are in **local** space, so walk the node tree and apply each node's
accumulated matrix to all eight corners of the box, then union. Report width/height/depth and
`min[1]`:

- `min[1] ≈ 0` → authored standing on the origin, attach directly.
- Otherwise offset by `-min[1]` at attach time, or the model floats or sinks.

## Size normalisation

Decide scale by **same-screen visual height**, not by matching raw numbers to a spec sheet.

1. Measure the on-screen height of the placeholder you are replacing.
2. Compute the initial scale ratio from the real asset height.
3. Confirm from a screenshot in the game camera, then adjust.

Record per-asset `scale`, `rotationY`, and `yOffset` in one table. Confirm facing from a render —
never from the axis you hope the exporter used.

Cases worth naming in the brief instead of discovering later:

- A model whose proportions contradict its written setting (a character specified as half human
  height, modelled at human height). Scale it in the game; log the asset as needing revision.
- Deliberately short creatures must end up visibly shorter than the human characters.
- Ghost/spirit characters needing transparency: replicate the intended alpha on the new material
  and check the transparent-vs-opaque sort order, or the character reads as solid.

## Integration acceptance checklist

Walk this list, actually looking at each screenshot:

- [ ] Placeholder and formal asset compared side by side (`?legacy-*` flag)
- [ ] Feet on the ground in every state (idle, walk, hit) — no float, no sink
- [ ] Walk cycle reads from silhouette alone at game camera distance
- [ ] Character/scene-prop scale ratio holds on screen
- [ ] Two characters on the same axis: occlusion order sensible, no interpenetration
- [ ] Both left and right facings read; turn transition clean
- [ ] Attachment points carry their props and follow limb motion
- [ ] Model-specific feedback still lands where it should (e.g. an effect meant to cover the eyes
      must actually cover them on the new mesh, not just tint the material)
- [ ] Missing/failed asset: game still playable, console clean
- [ ] Console and `pageerror` count zero on the normal path
- [ ] Screenshots are of the real game camera, at least 1200px wide

## Reporting the boundary honestly

Name what is still missing rather than letting a passing screenshot imply completeness. Typical
remainders after a first integration pass: no skeletal animation, no collision, no combat or hit
reactions, no final camera pass, and any asset whose proportions contradict its setting.
